## 1. The 98643A card

### 1.1 Register map

The card has a 64 KB window, `$750000-$75FFFF`. It is a DIO-I 16-bit card, and MAME maps it as `dio16`.

| Offset | Access | Function |
|---|---|---|
| `+$0000/1` | read | **ID** = `$15` \| (REMOTE switch ? `$80` : 0). The upper byte reads 0 (MAME returns the word `$0015`). |
| `+$0000/1` | write (any data) | **Card reset.** Resets the LANCE too: CSR0 = STOP, and IE, LOCK and ACK are cleared. NetBSD writes `$FF` to `+1`. The ROM does `move.w #1,(A0)` and `move.b #1,($1,A0)`. |
| `+$0002/3` | read/write byte at +3 | **Status/control**. Bits are listed in 1.2. |
| `+$4000` | 16-bit | LANCE **RDP**, the data port. |
| `+$4002` | 16-bit | LANCE **RAP**, the register address port. |
| `+$8000-$BFFF` | byte, word or long | **16 KB card RAM**. Big-endian words: the even byte is D15:8. NetBSD uses byte accesses (`bus_space_*_region_1`). The ROM uses words and runs `ram_test_range` over all of it. |
| `+$C000-$FFFF` | 16-bit read | **NOVRAM**: one nibble per 16-bit word, in D3:0. MAME returns `$FFF0 \| nibble`. Callers mask with `& $F`. |

The offset table is NetBSD's `lestd[] = { 0, 0x4000, 0x8000, 0xC008 }`. `dio_attach` maps `DIO_DEVSIZE` = 64 KB.

### 1.2 Status/control byte (`+3`)

| Bit | Name (NetBSD / MAME) | Behaviour to implement |
|---|---|---|
| 7 | `LE_IE` / `REG_SC_IE` | Interrupt enable. R/W. |
| 6 | `LE_IR` / `REG_SC_IP` | Read only. Equals the LANCE /INTR pin (CSR0.INTR && CSR0.INEA). **It is raw: it reads 1 even when IE = 0.** The ROM self-test depends on this (error `$12`). |
| 5:4 | DIO IPL field | Read only. The interrupt level minus 3, from the switches. NetBSD `DIO_IPL(va) = ((*(va+3) >> 4) & 3) + 3`. The MAME default is level 5, which reads `2`. |
| 3 | `LE_LOCK` / `REG_SC_LOCK` | R/W. |
| 2 | `LE_ACK` / `REG_STATUS_ACK` | Read only. MAME sets it on a write with LOCK = 1 and on **any** RAP/RDP read or write. Only a card reset clears it. |
| 1 | `LE_JAB` | NetBSD comments it as "loss of tx clock (???)". MAME reads 0. Return 0. |
| 0 | `REG_SC_REV` in MAME | MAME reads 1. In `sub_0488c` the ROM uses bit 0 to choose the media string it prints: 1 = "THIN", 0 = "AUI". |

- **Interrupt to the CPU** = IE && IP, on the configured level. Default to **5**, as MAME does. The 98644 serial already uses level 5 in `hp385_top`. Both drivers poll their card's status register, so sharing a level is fine.
- **The LOCK/ACK handshake.** NetBSD's `lewrcsr`/`lerdcsr` repeat every RAP write and every RDP access until `+3 & LE_ACK` is set. On real hardware the card probably held off host LANCE accesses while the LANCE owned the bus. In an FPGA, host register accesses never conflict with DMA, so use the MAME model: ACK sets on the first access and stays set.
- The ROM checks that **ACK reads 0 right after a card reset** (`+3 & $CC == 0`). It also reads CSR0 = 4 **without** polling ACK first. So a card reset must clear ACK, and register accesses must never depend on ACK.

### 1.3 How the LANCE reaches the card RAM

The LANCE masters only the card's 16 KB. It never touches host memory.

MAME's `lance_dma_in/out` index `m_ram[(addr >> 1) & 0x1FFF]`, so **LANCE address bits 23:14 are ignored**. Both software views depend on this:
- NetBSD uses `sc_addr = 0`, so its LANCE addresses are `$0000-$3FFF`.
- The boot ROM self-test uses LANCE addresses **`$8000+`**: CSR1 = `$8000`, RDRA = `$8018`, buffers at `$8028` and `$8048`.

Decode only A13:1 plus byte lanes.

Host accesses and LANCE DMA to this RAM do not conflict. Make it a true dual-port M10K: port A for the host, port B for the LANCE.

### 1.4 NOVRAM (station address)

There are 64 nibbles: two copies of 32, at `+$C000` and `+$C040`. A byte is two consecutive words, high nibble first. **Byte n is at `+$C000 + 4n`.**

| Byte | Words (MAME index) | Meaning |
|---|---|---|
| 0 | 0-1 | Copy selector. If it is non-zero, the ROM (`$E666`) switches to the copy at `+$C040`. `sub_0eb66` tests bit 0 of `+$C003`. |
| 1 | 2-3 | Included in the checksum. MAME has `$00`. |
| 2-7 | 4-15 | **Station address**, at `+$C008-$C01F`. MAME has `08:00:09:06:A1:F1`. |
| 8-14 | 16-29 | Included in the checksum. MAME has `$00`. |
| 15 | 30-31 | **Checksum** = (byte 1 + … + byte 14) & `$FF`. MAME has `$A9`, which is correct. |

How each reader uses it:
- **Boot ROM** (`sub_0e612`): reads byte 0 and picks the copy, then reads bytes 1-14 summing them, then compares with byte 15. It prints the MAC in the configuration list.
- **NetBSD** (`leattach`): reads 12 odd bytes, `+$C009, +$C00B, …, +$C01F`, two nibbles per MAC byte, with no checksum.
- **HP-UX 9**: not known. Assume it reads the same bytes and may also check the checksum, so make the checksum valid.

**Recommendation:** a 64 × 4 ROM/LUT, mirrored every `$80` across `+$C000-$FFFF`. Reads return `{12'hFFF, nibble}`. Writes are accepted and ignored, since it is a NOVRAM with a store sequence and nothing is known to write it. Build the MAC as:
- `08:00:09` (the HP OUI), then
- a fixed byte such as `$38`, then
- two bytes from an OSD "MAC suffix" option or a Main-supplied value.

Compute byte 15 in RTL.

### 1.5 MAME gaps not to copy

- `novram_r(offset)` indexes a 32-entry array for every offset up to `$1FFF`. That is an out-of-bounds read. `novram_w` masks with `& $3F`, which also does not fit the 32-entry array. The real part has 64 nibbles.
- `regs_r` returns `space.unmap()` (open bus) for CSR1-3 while not STOPped. Returning the register value is harmless.
- The `am79c90.cpp` TODO list includes "external loopback" and "hp9k/3xx diagnostic failures". The ROM's external-loopback test (§2, `sub_0e95a`) is unimplemented in MAME.

## 2. What the boot ROM does with the card (it must pass)

The ROM finds ID `$15` during the select-code scan (`$208C`) and calls `sub_0488c`:
1. Print the MAC (`sub_0e612`) and "AUI" or "THIN".
2. Run `sub_0e69e(card, 0)`, the internal test.
3. If the system-globals flag `($A,A5)` bit 0 is set, also run `sub_0e69e(card, 1)`, the external test. Its failure strings are "MAU" (`$1B`), "CABLE" (`$19`/`$1A`) and "NO HEARTBEAT" (`$23`).

The internal test is a precise behavioural spec. It is worth a unit bench of its own.

In the tables below:
- `A3` is `+$4000` (RDP) and `A2` is `+$4002` (RAP).
- "status" means the byte at `+3`.

### 2.1 Register test (`sub_0e784`)

| Step | Action | Must see |
|---|---|---|
| 1 | status ← 0 | status & `$88` == 0 |
| 2 | status ← 8 (LOCK) | status & `$08` set |
| 3 | `sub_0ea04`: up to 10 × {RAP ← 0, test ACK}, then CSR0 ← 4 | ACK within 10 tries (else code `$22`), then CSR0 reads back 4 |
| 4 | — | status & `$0C` == `$0C` |
| 5 | read RDP | `$0004` (CSR0 = STOP). Then CSR0 ← `$0002` (STRT, with no INIT done) |
| 6 | word write 1 to `+0` (card reset) | status & `$CC` == 0, so IE, IP, LOCK and ACK are all clear |
| 7 | read RDP (no ACK poll) | `$0004`. The reset must abort whatever step 5 started. |
| 8 | RAP ← 3, 2, 1, 0, reading each back | RAP reads back bits 1:0 |
| 9 | CSR1 ← 0, then `$FFFE` | reads back 0, then `$FFFE` |
| 10 | CSR2 ← `$FF`, then 0 | low byte reads back `$FF`, then `$00` |
| 11 | CSR3 ← 7, then 0 | bits 2:0 read back 7, then 0 |

After that, the ROM runs `ram_test_range` over `+$8000-$BFFF` and resets the card.

### 2.2 LANCE loopback test (`sub_0e88e`)

**Setup before each case** (`sub_0eb34`):
1. LOCK, then the ACK/STOP handshake.
2. status ← 0, so **IE stays 0**.
3. Copy a template into card RAM, then write TMD2.
4. Write CSR1 = `$8000`, CSR2 = 0, CSR3 = `$0004` (**BSWP**).
5. Write **CSR0 = `$004B` = INEA | TDMD | STRT | INIT, all in one write.**

**Template in card RAM.** Offsets are from `+$8000`. LANCE addresses are these plus `$8000`.

| Offset | Content |
|---|---|
| `+$00` | MODE (per case) |
| `+$02` | PADR `$0214 $2536 $4758`, which is MAC `14:02:36:25:58:47` (low byte first in each word) |
| `+$08` | LADRF, all 0. Case 4 sets byte `+$09` = `$08`, which is LADRF bit 3. |
| `+$10` | RDRA `$8018`, RLEN 0 (one descriptor) |
| `+$14` | TDRA `$8020`, TLEN 0 |
| `+$18` | RMD: `$8048 $8000 $FFE0 $0000` (OWN, 32-byte buffer at `+$48`) |
| `+$20` | TMD: `$8028 $8300 BCNT $0000` (OWN\|STP\|ENP, buffer at `+$28`) |
| `+$28` | Frame. dst `14:02:36:25:58:47`, src `00:01:02:03:04:05`, then `06…0F 11 12 13 14 15 16`. 28 bytes in total. |
| `+$44` | Expected FCS, or the software FCS for the DTCR cases |
| `+$48` | RX buffer |

**The cases:**

| # | MODE | Change | TMD2 | Compared (tx `+$28` vs rx `+$48`) |
|---|---|---|---|---|
| 1 | `$0044` LOOP\|INTL | `+$44` = `44 7B 9F B0` | -28 | 32 bytes: frame plus the **LANCE-made FCS** |
| 2 | `$004C` +DTCR | same | -32 | 32 bytes. The receiver checks the software FCS. |
| 3 | `$8044` +PROM | dst `51:04:36:25:58:47` | -28 | 28 bytes. Accepted only because of PROM. |
| 4 | `$004C` | LADRF bit 3 set, `+$44` = `AA 68 DB 66` | -32 | 28 bytes. Accepted through the **multicast hash**. |
| 5 | `$0044` | dst `FF:FF:FF:FF:FF:FF`, LADRF clear | -28 | 28 bytes (broadcast) |
| 6 | `$0054` LOOP\|COLL\|INTL | — | -28 | TMD3.**RTRY** (bit 10) must be set, and CSR0.ERR must be clear |

**Polling in cases 1-5** (`sub_0ea9e`):
1. Read CSR0 until ACK and IDON.
2. **status bit 6 (IP) must already be set.** Otherwise the ROM reports code `$12`.
3. Read CSR0 until TINT.
4. Read RMD1 and TMD3. If TMD3.RTRY is set, the case fails.
5. **Within 30 CSR0 reads, RINT must appear.**
6. Compare the buffers.
7. Require CSR0.ERR (bit 15), RMD1.ERR (bit 14) and TMD1.ERR (bit 14) all clear.

So a loopback frame must be received essentially together with TINT.

**Checked with Python** (zlib CRC-32 and a bit-reflected CRC):
- The FCS of the case-1 frame is `0xB09F7B44`. It lands in the buffer as bytes `44 7B 9F B0`, which is little-endian, the wire order. With BSWP = 1, the buffer bytes are in host byte order.
- The NetBSD-style hash `ether_crc32_le(51:04:36:25:58:47) >> 26` is 3.
- `AA 68 DB 66` is the FCS of the case-4 frame.

**External test** (`sub_0e95a`): runs only when the sysglob flag is set.
- It loads the real MAC from the NOVRAM into PADR.
- It uses MODE `$0004` (LOOP without INTL, through the MAU) and retries up to 6 times.
- It fails on:
  - IDON without TINT, or TINT without RINT
  - RMD1 BUFF/CRC (`& $1400`)
  - CSR0 BABL/MERR (`& $4800`)
  - RMD1.ERR
  - TMD3 BUFF/UFLO/LCOL/LCAR/RTRY (`& $DC00`)
  - **CSR0.CERR** (missing SQE heartbeat), which gives "NO HEARTBEAT"

**Implement LOOP without INTL exactly like internal loopback, and never set CERR.**

## 3. Am7990 essentials for the FPGA

### 3.1 Registers

- **RAP** holds bits 1:0 and reads back. Reset value 0.
- **CSR1, CSR2 and CSR3** are writable only while STOP = 1.

| CSR0 bit | Name | Semantics (datasheet / MAME `regs_w`) |
|---|---|---|
| 15 | ERR | Read only. Equals BABL \| CERR \| MISS \| MERR. |
| 14 | BABL | Write 1 to clear. MAME sets it on transmit > 1518 bytes. Optional. |
| 13 | CERR | Write 1 to clear. **Never set it** (no SQE test on a virtual link). |
| 12 | MISS | Write 1 to clear. Set when a frame arrives and the current RMD is not OWN. |
| 11 | MERR | Write 1 to clear. Never set (the BRAM always answers). |
| 10 | RINT | Write 1 to clear. |
| 9 | TINT | Write 1 to clear. |
| 8 | IDON | Write 1 to clear. |
| 7 | INTR | Read only. Equals BABL \| MISS \| MERR \| RINT \| TINT \| IDON. The /INTR pin is INTR && INEA. |
| 6 | INEA | R/W. The Am7990 accepts it only while not STOPped. NetBSD and the ROM write it together with STRT or after INIT. |
| 5 | RXON | Read only. Set by STRT unless MODE.DRX. **NetBSD resets the chip if it ever reads RXON = 0 or TXON = 0.** |
| 4 | TXON | Read only. Set by STRT unless MODE.DTX. |
| 3 | TDMD | Write 1 to set. Transmit poll now. Clears when the poll happens. |
| 2 | STOP | Write 1 to set. Overrides every other bit in the same write. Acts as a reset: CSR0 = `$0004`, CSR3 = 0, RX and TX off, and the ring positions are lost. |
| 1 | STRT | Write 1 to set. Clears STOP. |
| 0 | INIT | Write 1 to set. Reads the init block, then sets IDON and clears STOP. **INIT, STRT and TDMD can arrive in one write** (the ROM does this), giving init, then start, then a transmit poll. |

| Register | Content |
|---|---|
| CSR1 | IADR[15:1]. Bit 0 reads 0. The ROM writes `$FFFE` and expects `$FFFE`. |
| CSR2 | IADR[23:16] in bits 7:0. MAME stores bits 15:8 too on the 7990, but nothing needs them. |
| CSR3 | Bit 2 BSWP, bit 1 ACON, bit 0 BCON. Only BSWP matters. Reset value 0. **NetBSD and the ROM write `$0004`.** |

**Reset value:** CSR0 = `$0004`. CSR0 is cleared to that on card reset and on writing STOP.

MAME's IDON is visible after a delay of about 96 LANCE clocks, about 4.8 µs: (1 + 6 + 1) × 12 at 20 MHz (MAME commit `29bcc72` "delay interrupt after initialization"). At 33 MHz a BRAM init finishes in under 1 µs. **Keep a ~5 µs IDON delay**, in case some driver sets up its handler after writing INIT.

### 3.2 Init block (12 words at IADR, word-aligned)

| Word | Content |
|---|---|
| 0 | MODE. Bit 15 PROM, 6 INTL, 5 DRTY, 4 COLL, 3 DTCR, 2 LOOP, 1 DTX, 0 DRX. Bits 14:7 are reserved on the 7990. |
| 1-3 | PADR. **Low byte first**: word 1 = MAC[1]<<8 \| MAC[0], and so on. NetBSD `am7990_meminit` packs it this way. |
| 4-7 | LADRF[15:0], [31:16], [47:32], [63:48] |
| 8 | RDRA[15:0]. Bits 2:0 are 0, because descriptors are 8-byte aligned. |
| 9 | RLEN[15:13] (ring size 2^n, 1-128) \| RDRA[23:16] |
| 10 | TDRA[15:0] |
| 11 | TLEN[15:13] \| TDRA[23:16] |

NetBSD's `struct leinit` pads the block to 16 words. The LANCE reads only 12.

### 3.3 Descriptors (4 words, 8 bytes; never byte-swapped)

| Word | RMD (receive) | TMD (transmit) |
|---|---|---|
| 0 | LADR[15:0] | LADR[15:0] |
| 1 | OWN 15, ERR 14, FRAM 13, OFLO 12, CRC 11, BUFF 10, STP 9, ENP 8, HADR 7:0 | OWN 15, ERR 14, (ADD_FCS 13 on the C-LANCE only), MORE 12, ONE 11, DEF 10, STP 9, ENP 8, HADR 7:0 |
| 2 | `1111` \| BCNT (two's complement, 12 bits) | `1111` \| BCNT |
| 3 | MCNT[11:0], the byte count **including the FCS**, written in the ENP descriptor (0 on error) | BUFF 15, UFLO 14, LCOL 12, LCAR 11, RTRY 10, TDR 9:0 |

- BCNT: MAME's `get_buf_length(d) = (d == $F000) ? 4096 : -(int16)($F000 | d)`.
- On a big-endian card, word 1 = {bits, HADR}, so OWN is bit 15 of the word at offset +2. NetBSD's `lermd` puts `rmd1_bits` first on big-endian hosts for this reason.

### 3.4 BSWP and the data buffers

BSWP applies only to frame bytes. Descriptors and the init block are always native 16-bit words.

The card RAM holds big-endian words (host even byte = D15:8), so:

- **BSWP = 1**: frame byte k at buffer address A + k is exactly card-RAM byte A + k as the host sees it. The FPGA's port B is then a plain byte-addressed RAM.
- **BSWP = 0**: the two bytes of each word are swapped (Intel order). Support it, since it is one mux, but expect no client to use it.

Buffers may start or end on an odd byte. MAME handles that with masked first and last word writes. With a byte-enabled port B this is free.

### 3.5 Receive address filter

Accept a frame if any of these holds:
- MODE.PROM is set.
- dst == PADR (unicast).
- dst is broadcast. The 7990 has no broadcast disable.
- dst is multicast (dst[0] bit 0) **and** LADRF bit `h` is set.

The hash: `h = ether_crc32_le(dst, 6) >> 26`. The CRC uses the reflected polynomial `$EDB88320`, initial value `$FFFFFFFF`, and **no final inversion**. Bit `h` is word `h >> 4`, bit `h & 15` (NetBSD `lance_setladrf`). MAME's form, `BIT(ladrf, 63 - (zlib_crc >> 26))`, is the same thing. ROM case 4 confirms it with `h` = 3.

Main's RX header already carries `h` in bits 21:16 (§4.1). The FPGA still needs a CRC engine for loopback, though.

### 3.6 Transmit and receive behaviour

**Transmit:**
- Poll on TDMD, on STRT, and every 1.6 ms (MAME `TX_POLL_PERIOD`).
- If TMD1.OWN is set and STP is not, clear OWN and skip.
- Otherwise gather buffers until ENP, chaining across OWN descriptors.
- If a chained descriptor is not OWN: set TMD1.ERR and TMD3.BUFF|UFLO, and turn TXON off.
- Clear OWN on each descriptor and write TMD1 of the last one, then set TINT.
- Append the FCS unless MODE.DTCR. The FCS matters only for loopback: the wire path drops it, see §4.

**Receive:**
- If RXON is off, drop the frame. If it fails the filter, drop it.
- If the current RMD is not OWN, set MISS (no descriptor write).
- Otherwise:
  1. Set STP and scatter the frame across buffers, looking ahead at the next RMD's OWN.
  2. If the next RMD is not OWN, set ERR|BUFF (and OFLO).
  3. Set ENP on the last descriptor and write MCNT.
  4. Set RINT.
- The FCS is checked only in loopback with DTCR. Main appends a good FCS to every network frame.
- Drop runts under 64 bytes including the FCS, except in loopback.

**Loopback** (MODE.LOOP, with or without INTL):
- The transmitted frame plus its FCS (or with the software FCS when DTCR) goes through the receive filter and into the RX ring at once.
- Nothing reaches the network, and network RX is held off meanwhile.
- MAME rejects loopback frames over 32 bytes (without FCS) as invalid. The ROM uses 28 + 4.
- **LOOP + COLL** (forced collision): no receive; set TMD1.ERR, TMD3.RTRY and TINT. **Do not set CERR.**

### 3.7 What the software uses

**NetBSD/hp300** (`if_le.c`, `am7990.c`, `lance.c`):
- Attach:
  1. Write `$FF` to the ID register (reset).
  2. Read the MAC from the NOVRAM.
  3. Set `sc_conf3 = LE_C3_BSWP`, `sc_addr = 0`, `sc_memsize = 16384`.
  4. Write `LE_IE` to status.
- 16 KB gives **8 RX and 2 TX descriptors** (`lance_config`) and `LEBLEN` = 1536-byte buffers.
- Every frame sits in one buffer with STP|ENP. NetBSD never chains, and it calls a chained receive an error ("dropping chained buffer").
- Init sequence:
  1. CSR0 = STOP
  2. CSR3 = BSWP
  3. meminit
  4. CSR1/CSR2 = init address (0)
  5. CSR0 = INIT
  6. Poll IDON
  7. CSR0 = INEA | STRT
- Transmit: fill the TMD, then CSR0 = INEA | TDMD. Pads frames to 60 bytes.
- Interrupt: read CSR0, then write back `isr & (INEA|BABL|MISS|MERR|RINT|TINT|IDON)`. If RXON or TXON reads 0, reset.
- RX length = MCNT − 4.
- MERR leads to `lance_reset`.
- Every RAP/RDP access loops on ACK.

**HP-UX 9** (`lan01` in the dfile, `is_lan_sc` probes sc 21; `hpux9_boot.md` §4/§5): there is no source. It will use the NOVRAM MAC, and almost certainly CSR3 = BSWP and the ACK handshake (Utah's 4.3BSD driver, which NetBSD's comes from, was written against this card). Expect broadcast plus HP multicasts (HP Probe, 802.3/SNAP), so LADRF must work. It may use other ring sizes, chained receive buffers, or loopback in `landiag`.

**Measure HP-UX before writing RTL.** Run HP-UX 9 under the local MAME with a card in an empty slot: `hp9k380 -sl5 98643` (`hp9k360` family; `sl5` is empty). Either:
- build `../mame` with `VERBOSE (LOG_GENERAL|LOG_REG|LOG_INIT|LOG_RXTX)` in `am79c90.cpp`, or
- use debugger watchpoints on `$754000-$754003`.

Record CSR3, MODE, the ring sizes, and whether RX or TX chaining appears.

### 3.8 Minimum feature set

**Implement:**
- RAP, CSR0-3 with the exact semantics above
- INIT (12-word DMA), STRT, STOP, TDMD, the 1.6 ms TX poll
- TX and RX rings with chaining
- BSWP (both ways), odd-byte buffers
- PADR, broadcast, LADRF and PROM filtering
- MISS
- internal and external loopback with an FCS generator and checker
- forced collision (RTRY)
- BABL on transmit > 1518 (cheap)
- the /INTR output

**Leave out:**
- collisions, retries and back-off: DEF/ONE/MORE are always 0, and DRTY is ignored
- TDR, always 0
- LCAR, LCOL and UFLO from timing (UFLO only on the chain-not-OWN case)
- FRAM and OFLO from the wire
- MERR, ACON and BCON
- the C-LANCE ADD_FCS bit (the 98643 has a 7990)
- real 10 Mb/s transmit timing

Pace receive delivery (§5.4).

## 4. The MiSTer side: how frames reach Linux

### 4.1 The HP 9000 family bridge (`support/hp9k/hp9k_enet.cpp`): reuse this

This bridge is already in the user's `hp9k-family` branch of Main and is used by the 715. It is a byte-for-byte copy of `support/sun/sun_enet.cpp`, which the Sun cores use with their LANCE, ts_lance.

- **The NIC stays in the FPGA. Main is only the wire.**
- Frames cross a **DDR3 mailbox at ARM physical `0x1FF0_0000`**, 64 KB. That is Avalon word address `0x03FE_0000` (= `>>3`). It sits outside every core's own region. It is shared by convention with the A2065, NeXT, Sun and 715 bridges, which is fine because only one core runs at a time.
- All fields are 64-bit little-endian words.

| Offset | Writer | Content |
|---|---|---|
| `+$0000` MAGIC | FPGA, **last** at start-up | Names the core and its RX ring depth. Main ignores the mailbox until it knows the magic (`rx_ring_slots()`). The 715 uses `"HPETH001"` = `$4850455448303031` with 16 slots. |
| `+$0008` GEN | FPGA | A new value at every FPGA start. Main resynchronises its pointers. |
| `+$0010` TX_WPTR | FPGA | Frames posted (free-running) |
| `+$0018` TX_RPTR | Main | Frames taken |
| `+$0020` RX_WPTR | Main | Frames posted |
| `+$0028` RX_RPTR | FPGA | Frames taken |
| `+$0030` MAC | FPGA | Bit 63 valid, bits 47:40 the first byte … bits 7:0 the last. Main uses it for the BPF filter (eth0) or the macvlan MAC. |
| `+$1000` TX ring | FPGA | 8 slots × `$800`. Word 0 bits 10:0 = length. Frame byte i is in byte lane i mod 8 of word 1 + i/8. **No FCS.** |
| `+$5000` RX ring | Main | 16 slots × `$800`. Word 0 bits 10:0 = length **with FCS** (Main pads to 60 and appends the FCS), bits 21:16 = LADRF index of the destination. Then the frame. |

**Start-up order** (`i82596.sv` `S_BOOT`):
1. MAGIC ← 0
2. GEN ← new value
3. all four pointers ← 0
4. MAC
5. MAGIC last

**Main side:**
- `hp9k_enet_poll()` runs in the poll loop. It drains TX into `ethernet_send()` and fills RX from `ethernet_recv_nb()`, dropping frames when the ring is full.
- The link modes come from the A2065 network layer (`minimig_a2065_ethernet.cpp`):
  - eth0: raw AF_PACKET in promiscuous mode with a cBPF filter on the guest MAC
  - eth1
  - macvlan `hp9k0` on eth0
  - tap0
- It turns off GRO and other offloads so that no frame exceeds 1518 bytes.

**Main patch needed for the 385** (local only, `support/hp9k/hp9k.cpp` and `hp9k_enet.cpp`):
1. Change the models row to `{ "HP9K385", HP9K_385, 2, "[14:12]" }`. It currently has `0` = "no LAN bridge yet".
2. Add a magic in `rx_ring_slots()`, for example `"H3ETH001"` = `$4833455448303031` returning 16.

`hp9k_enet_start()` already returns early for models without network bits.

**Core OSD:** copy the 715 line exactly: `"O[14:12],Network,eth0,Off,eth1,macvlan,tap0;"`. OSD value 0 means eth0 and 1 means Off. Status bits 14:12 are free in `HP9K385.sv`.

**Caveat:** in eth0 mode the BPF filter (`ethernet_set_mac_filter`) passes only frames to the guest MAC and broadcasts. **Multicasts are dropped**, despite the log text. HP Probe and other HP multicasts reach the guest only with macvlan, eth1 or tap0.

### 4.2 The 715's FPGA side: the RTL pattern to copy

- `../hp9000-715/rtl/lasi/i82596.sv` holds the mailbox client inside the NIC: `nb_req/nb_we/nb_addr[12:0]` (64-bit word offset)/`nb_wdata/nb_ack/nb_rdata`, one word at a time, held until ack.
  - It keeps a 2 KB byte frame buffer (`fbuf`).
  - TX: frame → fbuf → slot words → TX_WPTR++.
  - RX: when RX_WPTR ≠ RX_RPTR, it copies the slot into fbuf, checks the address, delivers, then does RX_RPTR++.
- `../hp9000-715/rtl/mister/ddr3_port.sv` arbitrates the `nb_*` port with the other DDR3 clients (`NB_BASE = 29'h03FE_0000`, `S_CMD` and `S_RDATA` paths).

### 4.3 The SS20 core's LANCE wire: closest in spirit

`danifunker/NewSunSparcStation20_MiSTer` `rtl/mister/eth_hps.vhd` (GPL-2.0-or-later, the user's own) puts the same mailbox (`"SSETH002"`) behind a **LANCE**. Its header documents lessons worth keeping:
- TX words carry byte enables, because buffers can start or end on odd bytes.
- While the TX ring is full the transmitter waits ("busy wire"). A frame is dropped if Main takes nothing for `TXWAIT` (50 ms, meaning Main is not running) or when the network is Off.
- **RX pacing.** A frame is offered only after its wire time at 10 Mb/s: (bytes + FCS + 8 preamble + 12 gap) × 0.8 µs. Hosts hand over fragment bursts that an 8-descriptor guest ring cannot absorb.
- RX frames longer than 1522 bytes are dropped. The guests' buffers are 1536 bytes.
- Loopback bypasses the mailbox, and network RX is not polled meanwhile.
- A frame the LANCE never takes (receiver off) is dropped after a stale timeout or at INIT.

Its LANCE (`ts_lance`) is Grabulosaure's and not reusable (§5). Its port types come from `ts_pack`, so port the ideas to SystemVerilog rather than the file.

### 4.4 `danifunker/Main_MiSTer` `mac-ethernet-pr`: a different model

Branch `origin/mac-ethernet-pr`, head `b95473b`. The Ethernet commit is `0b7d589` "Mac: Ethernet card support (Apple Ethernet LC and NB Twisted Pair)". Files:
- `support/mac/mac_eth.{h,cpp}`
- `mac_eth_iface.cpp`
- `mac_sonic.{h,cpp}`
- `mac_eth_declrom.h`

Here **the chip model, a DP83932 SONIC, runs on the ARM**. The FPGA forwards register accesses instead of frames:
- **Window** at the same ARM physical `0x1FF0_0000`, `ETH_WIN_SIZE` `$29000`. Two layouts:
  - LC v2 (`"McLCETH2"`): a 64 KB guest-RAM DMA bounce buffer, the declROM, and a control block at `$20000`. A DMA-RPC engine (`ETH_CTL_DMACMD/DMASTAT`) lets the ARM master guest RAM through the FPGA.
  - NB v3 (`"McNBETH3"`): **128 KB card RAM lives in the window**, so the guest's card-RAM accesses go to DDR3. Then 32 KB of raw declROM, and the control block at `$28000`.
- **Control block:**
  - `MAGIC` (ARM→FPGA, written last)
  - `WPTR` (FPGA doorbell write index)
  - `SHAD` (64 × 16-bit register shadow for guest reads)
  - `INT` (bit 0 = the SONIC INT line)
  - `MACPROM`, `GEO`, `RPTR` (ARM read index, backpressure)
  - `RING` at `+$800`: 256 × u64 `valid | tag[3:1] | reg[9:4] | data[31:16] | seq[39:32]`. Tag 0 is a register write and tag 1 a reset.
- **Network** (`mac_eth_iface.cpp`): `tapN` opens `/dev/net/tun` (IFF_TAP | IFF_NO_PI); anything else uses a raw AF_PACKET socket with filters.
  - MAC `08:00:07:4D:{4C|56}:suffix` from an OSD nibble, which can be overridden by `<HomeDir>/eth.cfg` (`iface=`, `mac=`).
  - The interface comes from the `[37:36]` OSD bits.
- **The Quadra 800** (`../MacQuadra800_MiSTer/rtl/sonic_mbx.sv`, Main `support/mac/mac_eth_q8.*`, local master `f6a3caa`) refines this to window v4 `"McQ8ETH4"`:
  - ISR and IMR are kept in the FPGA for exact interrupts.
  - CR command bits read back as set until the ARM has applied them.
  - An ordered list of up to 8 DMA ops runs through a 16 KB XFER area.
  - DEBUG and SAMPLE words support profiling.

**Upstream Main also already has a LANCE model of this kind:** the Minimig **A2065** (Am7990 + 32 KB board RAM).
- Main `support/minimig/minimig_a2065_{registers,rings,ethernet,...}.cpp`, ported from Amiberry `a2065.cpp`, GPL.
- FPGA side: `MiSTer-devel/Minimig-AGA_MiSTer` `rtl/A2065/{a2065.v, a2065_regfile.v, a2065_ddr3_mailbox.v, a2065_ddram.v}`.
- Board RAM is at `0x1FF0_0000 + 0` (32 KB). The CSR doorbell ring is at `+$8800`, with WPTR `+$8008`, a CSR0-3 shadow at `+$8010`, the INT state at `+$8018` and the MAC at `+$8028`.
- Its card is the closest relative of the 98643. That makes it Option B below.

### 4.5 The interface our core must implement (Option A, recommended)

| Signal or field | Meaning |
|---|---|
| `nb_req, nb_we, nb_addr[12:0], nb_wdata[63:0] → nb_ack, nb_rdata[63:0]` | One mailbox word at `0x1FF0_0000 + 8 × nb_addr`, the same as `i82596.sv`. |
| MAGIC / GEN / pointers / MAC | Start-up order as in §4.1. Write MAC again at every LANCE INIT, from PADR. |
| TX slot | `{53'0, len[10:0]}` then the frame. **Strip the FCS:** never append it in TX, and when DTCR = 1 drop the last 4 bytes the guest supplied. |
| RX slot | Read `len` and `hash` from word 0. The frame includes Main's FCS. Pass it to the receive path, where MCNT = len. |
| `ena` | OSD Network ≠ Off. When off, still accept TX (drop it) so the guest sees normal TINTs. |

## 6. Recommended architecture

### 6.1 Option A (recommended): LANCE in the FPGA, Main as the wire

```
 CPU (io16 bus, $750000-$75FFFF)
   |  ID/status (+0..3)   RAP/RDP (+$4000/2)   RAM (+$8000-$BFFF)   NOVRAM (+$C000-$FFFF)
   v                        v                      v port A              v
 hp98643.sv ------------ lance.sv ----port B---- lan_ram (8K x 16 dual-port M10K)
   | irq (IE && IP)          | frame stream (fbuf 2 KB, bytes + be)
   v                         v
 irq_lvl[5]              lan_wire (mailbox client, nb_* port)
                             |
                         vram_ddr3 / small DDR3 arbiter -> DDRAM -> 0x1FF0_0000 <- Main hp9k_enet.cpp -> eth0/eth1/macvlan/tap0
```

**New RTL:**
- `rtl/hp98643.sv`, the card shell:
  - ID, status (IE, IP, level, LOCK, ACK, bit 0) and reset
  - NOVRAM LUT and checksum
  - the RAP/RDP passthrough
  - RAM port A
  - IRQ
  - Ports in the `hp98644` / `hp98265a` style (`reg_cs/reg_we/reg_off/reg_be/reg_din/reg_dout/irq`), plus a `reg_wait` (see integration).
- `rtl/lance.sv`, the Am7990: CSRs, init, TX/RX ring walkers, filter, CRC-32, loopback, TX poll timer, IDON delay. It has a 16-bit byte-enabled RAM port (port B) and a byte-stream frame interface to the wire.
- `rtl/lan_wire.sv`, the mailbox client:
  - magic, GEN, pointers, MAC word, TX/RX slot copy through a 2 KB `fbuf`
  - RX pacing at 10 Mb/s
  - TX-full wait and timeout
  - drop when OSD Off
  - Put the CRC/hash pre-check here or in `lance.sv`. Loopback stays inside `lance.sv`.
- RAM: 16 KB = 8K × 16 = 128 kbit, about 13-16 M10K. `fbuf` is 2 M10K.
  - **Infer both in a separate RAM module.** The memory note says arrays inside generate blocks become flip-flops. `rtl/wombat/dpram.v` or the `upi41` M10K style both work.
  - Total LAN BRAM is under 20 of the 553 M10K. Logic is probably 1-2k ALMs.

**Integration in `hp385_top.sv` / `HP9K385.sv`:**
- **Decode** `s_la[31:16] == 16'h0075` as `R_IO16`, `DEV_LAN`. For the ROM's scan, the whole 64 KB must answer (no bus errors) only while the card is enabled.
  - Consider an OSD "LAN card: present / absent" option, so a bad card cannot stop a boot. Absent means bus error, which is the current behaviour.
- **io16 timing.** `io16_rdata` is sampled in the same clock as `io16_cs`, and every current device answers combinationally. The card RAM is a synchronous M10K, so generalise `io16_wait` (today only Catseye writes use it) into a per-device ready. Give RAM reads one wait cycle.
- **IRQ.** OR `lan_irq` into `irq_lvl[5]` (fixed level 5, status bits 5:4 = 2), or make it a parameter.
- **Reset.** The card reset comes from `dio_reset` or from the ID write. `lance.sv` must abort any DMA in progress (ROM step 7).
- **DDR3.** Today `vram_ddr3` is the only client. Add a mailbox port the way the 715's `ddr3_port.sv` does:
  - single 64-bit beats at `NB_BASE = 29'h03FE_0000`
  - lowest priority after scanout
  - mailbox traffic is tiny: at most a few thousand words per second at 10 Mb/s
- **OSD.** Add `"O[14:12],Network,eth0,Off,eth1,macvlan,tap0;"` and optionally a MAC-suffix option. Pass `ena = status[14:12] != 3'd1` into `lan_wire`.
- **Main.** Two lines, per §4.1, committed with the existing local `hp9k-family` work (not pushed).

**Why Option A:**
- The ROM self-test needs exact register read-back immediately after writes and immediately after a card reset.
- The loopback RINT must appear within about 30 CSR0 reads of TINT.
- The test runs with IE = 0, so IP must be raw.
- All of that is trivial in RTL and fragile behind an ARM poll loop.
- The Main side already exists and is shared with the 715.
- A 10 Mb/s LANCE is not a resource problem.

### 6.2 Option B (fallback if area runs out): LANCE on the ARM, A2065-style

- Card RAM in the DDR3 window, so host RAM accesses wait on a DDR3 round trip.
- RAP/RDP writes go to a doorbell ring.
- CSR reads come from a shadow, and the INT line from the ARM.
- Port the Main `minimig_a2065_*` model and add an `hp9k` personality.

For this to pass the ROM test, the FPGA would still have to:
- keep RAP and CSR1-3 locally
- keep CSR0's reset value locally
- make ACK the "ARM has applied the doorbell" handshake

Even then, the 30-poll loopback window depends on Main's poll latency. Not recommended.

### 6.3 Pieces reused vs new

| Piece | Source |
|---|---|
| Main bridge, link modes, BPF, macvlan, tap, offload handling | **Reused**: `support/hp9k/hp9k_enet.cpp` plus the A2065 network layer (two-line patch) |
| Mailbox layout and start-up protocol | **Reused** from `i82596.sv` / `eth_hps.vhd` (re-implemented in SV) |
| DDR3 single-word client | **Pattern** from `hp9000-715/rtl/mister/ddr3_port.sv` |
| RX pacing, TX wait/timeout, RXMAX | **Ideas** from `eth_hps.vhd` |
| Dual-port RAM | **Reused**: `rtl/wombat/dpram.v` or a new `lan_ram.sv` |
| `hp98643.sv`, `lance.sv`, `lan_wire.sv`, CRC-32 | **New** |

## 7. Test plan

Sims stay short, per the memory notes: unit benches first, then a few million cycles of the full-system sim at most.

1. **`tb/tb_lance.sv`** (Verilator `--binary --timing`, in the `tb/README.md` style), with a behavioural CPU driving `hp98643.sv` + `lance.sv`:
   - **ROM register test** (§2.1), steps 1-11, including STRT before reset and CSR0 = 4 right after the ID write.
   - **ROM loopback cases 1-6** (§2.2): the exact template, CSR0 = `$004B`, IE = 0, IP raw. Check the bytes `44 7B 9F B0`, the DTCR software FCS, PROM, the LADRF hash index 3, broadcast, and forced-collision RTRY with ERR clear.
   - **NetBSD sequence:**
     1. ID ← `$FF`
     2. NOVRAM read: the MAC and checksum match
     3. STOP, CSR3 = 4, init at 0 with 8 RX and 2 TX descriptors, INIT, IDON, INEA|STRT
     4. Do every access through the ACK loop.
   - **Ring tests:**
     - TX with 1, 2 and 3 chained buffers, including odd start and end addresses
     - TX chain hitting a non-OWN descriptor: BUFF|UFLO and TXON off
     - RX chaining across 3 buffers
     - RX with no OWN: MISS
     - wrap-around of 1-, 2-, 8- and 128-entry rings
     - BSWP = 0 vs 1 byte order
     - unicast, broadcast, multicast-hit, multicast-miss and PROM filtering
     - W1C of each CSR0 bit, STOP overriding INIT/STRT
   - Mutation-check it like the other benches: a dropped BSWP, a wrong hash bit order, and ACK not cleared on reset must all be caught.
2. **`tb/tb_lan_wire.sv`.** `lan_wire` plus `lance.sv` against an Avalon DDR3 model (reuse `tb_vram_ddr3`'s random waitrequest model) with a fake "Main" process that:
   - echoes every TX slot back as an RX slot, with FCS and hash added the way `hp9k_enet.cpp` does
   - checks MAGIC is written last, GEN and the pointer reset, MAC from PADR, no FCS in TX slots, DTCR stripping, RX pacing, the TX-full wait and timeout, and the drop when Off
3. **Full-system Verilator** (`make -C verilator run`): the boot ROM lists `HP98643 (LAN)` at select code 21 with MAC `08:00:09:…` and passes its self-test. Compare against MAME `hp9k380 -sl5 98643`. Keep the run short.
4. **Board, NetBSD/hp300** (needs no guest configuration of the user's HP-UX image):
   - Check the `le0 at dio0 scode 21 ipl 5: address 08:00:09:…, 8 receive buffers, 2 transmit buffers` attach line.
   - Then `ifconfig le0 <addr>`, ping the MiSTer and the LAN, and ARP.
   - Run a bulk transfer (ftp or nc) both ways to check pacing and the absence of `le0: receive buffer error`.
   - Use tap0 mode for a host-only test, and macvlan for multicast.
   - Optional: netboot NetBSD through the ROM's LAN boot (`rbootd` on a host). This exercises the ROM's own LANCE driver.
5. **Board, HP-UX 9:**
   - `lanscan` should show hardware path 21 and station address `0x080009…`.
   - `landiag` reset and the self-test should pass.
   - `/etc/lanconfig`, `ifconfig lan0`, ping, telnet and NFS.
   - Per the memory note, **ask the user before touching any HP-UX network configuration** (`/etc/netlinkrc`, the hostname/IP prompts). Use `misterkvms-cli` for the console, and shut the guest down cleanly before swapping images.
6. **Regression:** with the OSD set to Off, or the card absent, the boot and the HP-UX boot match today's (`hpux9_boot.md` §5: "LAN … find nothing and stay quiet").
